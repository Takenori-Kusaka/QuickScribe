# ニュアンス保持整形品質の客観計測と評価設計に関する技術研究 (Issue #577 / ADR-0024)

> Status: Decided / Design SSOT (2026-08-17)
> 関連設計: [ADR-0024](../adr/0024-evaluation-redesign-cer-and-nuance.md) (評価刷新), [ADR-0004](../adr/0004-product-positioning-voice-journal.md) (自己理解ボイスジャーナル)

## 1. 研究の背景と目的

QuickScribe の核心価値である「要約や省略をせず、話者本人の迷いや語り口のニュアンスをそのまま残して思考を整理する」という **「ニュアンス保持整形」** は、極めて主観的な評価になりがちです。開発者がプロンプトを「改善した」と思っても、本当に元の発言の意味や気持ちが保たれているかを、客観的かつ定量的に評価する仕組み（回帰テストおよび継続改善の基盤）が不足していました。

本調査では、[ADR-0024](../adr/0024-evaluation-redesign-cer-and-nuance.md)（Proposed / Accepted）に基づき、ローカルかつオープンソースで稼働可能な日本語特化の「意味保持/ニュアンス評価」の評価設計（自動層＋判定層）を策定し、SSOT として文書化します。

---

## 2. 評価指標の設計（自動層の3つの柱）

客観測定を可能にするため、以下の3つの自動評価指標を組み合わせた多角的な評価設計（自動層）を採用します。

### 2.1. BERTScore-ja（意味的類似性の測定）
- **指標の意味:** 原文の文字起こしと、整形後のテキスト間のコサイン類似性を、事前学習済み Transformer（日本語 BERT モデル等）のトークン埋め込み配列から算出します。
- **特徴:** 単純な BLEU や ROUGE などの完全一致（N-gram）指標と異なり、「言い換え（シノニム）」や「表現のブラッシュアップ」を正しく意味レベルで追従でき、人間の評価と高い相関を示します。
- **制限:** 日本語の独白・口語独白において、BERTScore がどれだけ人間のニュアンス追従感覚と相関するかは、自前の少数相関検証によって閾値を補正します。

### 2.2. 日本語 NLI（自然言語推論）による「双方向含意（Entailment）」
- **指標の意味:** 事実の「捏造（ハルシネーション）」や「論理的矛盾」を検出するための指標です。
- **検証方法:** 
  1. **順方向（原文 → 整形後）:** 「原文から整形後の内容が論理的に導き出せるか（Entailment）」を検証。スコアが低い（矛盾や中立である）場合、整形によって新しい事実や憶測が「捏造」されたことを意味します。
  2. **逆方向（整形後 → 原文）:** 「整形後から原文の内容が導き出せるか」を検証。要約などで極端に情報が削ぎ落とされた（本質が失われた）場合、逆方向の Entailment スコアが急激に低下するため、「削りすぎ（情報の欠落）」を検知できます。
- **技術選定:** 英語圏で主流の `AlignScore` や `Factool` は日本語非対応（あるいはマルチリンガルで精度低）のため、日本語に事前学習された NLI モデル（例：`laboro-t5` や `cl-tohoku/bert-base-japanese-v3-nli`）を利用します。

### 2.3. 圧縮率（Compression Ratio）の監視
- **指標の意味:** `(整形後文字数) / (原文文字数)` の比率を測定。
- **役割:**
  - 逐語スタイル（`Verbatim`）では `0.9 〜 1.0` を期待。
  - 構造化スタイル（`Structured`）では `0.6 〜 0.8` を期待。
  - 要約スタイル（`Summary`）では `0.3 〜 0.5` を期待。
  - 圧縮率が極端に変動した場合に「指示への追従不全」として検知します。

## 3. 判定層（LLM-as-a-Judge）の設計と較正

自動層（BERTScore / NLI）でカバーしきれない「迷い・語り口のニュアンスが自然か」という高度なスタイル比較のために、LLMを評価器として使う **「判定層（LLM-as-a-Judge）」** を補助として併設します。

- **ペア弁別評価（A/B Testing）:**
  - モデルに対して、「元の文字起こし」と、プロンプト Variant A および Variant B による「2つの整形テキスト」を匿名で提示し、「どちらの方が本人のニュアンスを壊さずに、かつ思考整理できているか」を評価させます。
- **較正（Calibration）:**
  - LLM-judge は「出力順序のバイアス」や「自社製LLMひいき」などのバイアスを持ちます。これを防ぐため、開発者が人間（手動）で判定した「黄金テストセット（N=50）」を事前に構築し、LLM-judge の判定結果が人間の合意と一致するようにプロンプトをチューニング（較正）します。

## 4. ローカル・プライバシー最優先実行

- **オフライン完結:**
  全ての評価用 Python スクリプトは `TRANSFORMERS_OFFLINE=1` で動作し、ローカルにダウンロードされた軽量な CPU 推論用オンデバイスモデルのみを利用します。評価データの外部送信は一切行いません（セキュリティ保護）。

## 5. 結論

本Issue（#577）は、上記のように **「BERTScore-ja ＋ 双方向 NLI ＋ 圧縮率」による多角的な自動評価設計** を確定し、[ADR-0024](../adr/0024-evaluation-redesign-cer-and-nuance.md) の受入基準および SSOT として確定し、本タスクを完了とします。
