# ローカル完結型セマンティック検索と横断発見（「育てる」機能）の技術調査・設計研究 (Issue #579)

> Status: Decided / Design SSOT (2026-08-17)
> 関連ポリシー: [ADR-0015](../adr/0015-introspective-tags-and-cross-entry-discovery.md) (自己反省・横断発見), [ADR-0004](../adr/0004-product-positioning-voice-journal.md) (自己理解ボイスジャーナル)

## 1. 研究の背景と目的

QuickScribe は単なる「文字起こし機」ではなく、書き留めた複数の声（エントリ）から、ユーザー自身が「問い・傾向・気づき」を自発的に創発させていく **「残して育てる（横断発見）」** をコア体験として掲げています。
現状、エントリ一覧とキーワードによる全文検索（PR #673 で実装）までは完了していますが、意味ベースの関連提示（Smart Connections 的な意味的類似性）や、過去を振り返る仕組みは未実装です。

本調査では、ローカル完結型プライバシーと軽量性を完全に死守しつつ、Zettelkasten思想に基づく「下から創発する接続」をプロダクト内で実証するための技術スタック、UX上の安全制限、および実装ロードマップを定義します。

---

## 2. 倫理的・UX上の設計原則（DiaryMate / MindfulDiary 準拠）

CHI 2024 等のジャーナリング支援研究（`DiaryMate`, `MindfulDiary`）および「LLMによる表現の均質化リスク（arXiv 2508.01491）」に基づき、AIによる自己理解支援がユーザーの**当事者性を奪わない（均質化しない）**ための5大UX規律を厳格に定めます。

1. **代筆・要約置換の完全禁止（レイヤー設計）**
   - AIがユーザーに代わって感情を代筆したり、原文をAI要約で置き換えて「わかった気にさせる」ことを禁止します。原文（声のニュアンス）は常に主役であり、AIの解釈は補助的なレイヤーとして重ねて提示します。
2. **「決めつけ（ラベル貼り）」の禁止、問いかけ（Reflective Questioning）への変換**
   - 「あなたの現在の感情は『怒り』です」や「現在のテーマは『転職の悩み』です」といった、AI側からの断定的なラベル貼りを禁止します。
   - 代わりに「AのエントリとBのエントリで、同様の『迷い』のフレーズが観察されています。今はどのようなお気持ちですか？」といった、自己反省を促す問いを返します。
3. **接続（関連性）は提示、解釈はユーザー**
   - 関連する過去のエントリを意味的類似性で並べる（Related Entries）だけであり、なぜそれらが関連しているかの最終決定・意味づけはユーザー自身の頭脳に委ねます（Smart Connections 方式の忠実再現）。
4. **オプトイン・非侵襲（Non-intrusive）**
   - これらの自己洞察機能はすべてオプトイン（初期状態は無効、または呼び出し時のみ実行）とし、声を吐き出す瞬間の「書く体験」を絶対に邪魔しないようにします。

## 3. 推奨技術スタック（ローカル完結・軽量）

1. **埋め込みモデル（Embeddings）:**
   - **候補:** `Ruri-v3-small` / `Ruri-v3-base` (cl-nagoya, Apache-2.0, 130M/310M)。
   - **実行方式:** ローカル Ollama 上の GGUF、または WebONNX 経由の純 Rust（`ort`）インプロセス実行。モデル容量が130MB前後と極めて軽量であり、日本語の口語独白に対して高い意味的コサイン類似性（Retrieval 精度）を発揮します。
2. **ベクトルインデックス / 検索（Vector DB）:**
   - **第一候補:** **SQLite 内メモリ / シンプルコサイン類似性。** QuickScribe の想定エントリ数は個人利用で数千件規模（~5000件）に収まるため、高度な HNSW インデックス（`sqlite-vec` 等）を導入せずとも、Rust 側で愚直に浮動小数点配列（1024次元）のコサイン類似度を総当たり計算（Brute-force）するだけで、ミリ秒オーダーの超高速応答が可能です。これにより、複雑な C 依存関係（Tauriでのビルド不安定性）を回避し、最高度のポータビリティを維持します。

## 4. 段階的実装ロードマップ

### 4.1. Phase 1-A: 「On This Day（過去の今日）」の先出し（低コスト）
- **内容:** 埋め込みモデルを一切必要としない、最も実装コストが低く効果の高い「時系列リサーフェス（Day One 方式）」を先出し実装します。
- **仕様:** 過去の同じ月日（例：1年前の8月17日、2年前の8月17日）に書かれたエントリが存在する場合に、タイムラインの上部に「過去の今日の振り返り」として控えめに提示します。

### 4.2. Phase 1-B: ローカルセマンティック検索と「Related Entries」
- **内容:** `ruri` 埋め込みモデルを用いた意味的類似エントリの提示。
- **仕様:** 
  1. ユーザーが現在開いているエントリ（`transcript`）のテキストから、バックグラウンドで埋め込みベクトルを生成。
  2. 既存の全エントリの埋め込み（JSON or SQLite メタデータ領域にキャッシュ）とコサイン類似度を算出。
  3. 類似度が高い上位3件を「関連する過去の思考（Related Entries）」としてフッターに表示し、ユーザーがクリックして過去の文脈を Zettelkasten 的に辿れるように接続。

### 4.3. Phase 2: リフレクティブな問いの生成（ローカルLLM）
- **内容:** Ollama 等のローカル小型LLM（Llama-3-8B等）を用いた、横断的な「問い」のオプトイン生成。
- **仕様:** クラスタリングされた類似エントリのペアに対し、「断定せず、ユーザー自身の思考を促すオープンな問い」をプロンプトから生成します。

## 5. 結論

本Issue（#579）は、上記のように **「代筆せず問いを返す」UX規律** と、**「SQLite/in-memoryでの総当たりコサイン類似度」というRust依存を増やさない軽量アーキテクチャ** に基づき実装を行います。
本計画書を製品のバックログおよび設計指針（SSOT）として確定し、本タスクを完了とします。
