# 複数ジョブキューのキャンセル・再試行・再起動に関する永続化方針 (Issue #621 / S6.2 / ADR-0026)

> Status: Accepted / Decided (2026-08-17)
> 関連ポリシー: [ADR-0026](../adr/0026-multi-background-transcription-jobs.md) (マルチジョブキュー), [ADR-0006](../adr/0006-scope-completeness-policy.md) (スコープ完全性ポリシー)

## 1. 概要

QuickScribe の複数バックグラウンドジョブキュー（ADR-0026）は、録音停止ごとにジョブを非同期で発番し、FIFO（先入れ先出し）で逐次処理することで、連続した録音時に前ジョブの取りこぼしを防ぐ仕組みです。

本ドキュメントは、[ADR-0026](../adr/0026-multi-background-transcription-jobs.md) の **Phase 3（キャンセル/再試行/永続化）** における、アプリケーション再起動時、キャンセル時、エラー（失敗）時のキュー状態および音声バッファのライフサイクルと永続化方針を定義します。

---

## 2. 操作方針の定義 (Operations Policy)

各ジョブの状態（`queued`, `running`, `done`, `error`, `canceled`）に応じたローカル操作のライフサイクル設計です。

### 2.1. キャンセル操作 (`cancel_job`) - 実装済 ✅
- **対象状態:** `queued` (キュー滞留中) または `running` (現在実行中)
- **バックエンド挙動:** 
  - ジョブ状態を `Canceled`（キャンセル済み）へ遷移させ、フロントエンドに通知。
  - キューから除外されたジョブのメモリ上の未処理音声バッファ（`PendingWork`）を**即座に RAM から解放（`drop_orphan_pending`）**。これにより、キャンセル後に大容量音声バッファが居座り続けるメモリリークを構造的に防止。
- **UI表示:** `queued` / `running` 状態のジョブの横に **「中止 (Cancel)」** ボタンを表示。

### 2.2. 再試行操作 (`retry_job`) - 非採用（仕様制限） 🚫
- **背景:** QuickScribe はローカル完結型であり、ユーザーの PC リソース（RAM）の効率的な消費を重視します。そのため、ジョブが `Running` に移る（pick される）時点で、RAM 内の音声バッファはキューから即時削除されます。
- **結論:** ジョブが `error` (失敗) または `done` (完了) になった時点では、**RAM 内の該当音声データは既に破棄されて存在しないため、同一音声のまま「再試行」することは物理的に不可能**です。
- **トレードオフと代替策:** 
  - メモリリークおよびディスク圧迫を防ぐための意図的な仕様制限（制限A）です。
  - もし文字起こしが一時的な接続エラー（クラウド等）で失敗した場合、ユーザーは再度録音するか、音声ファイル保存設定（`save_audio: true`）が有効な場合に保存された WAV/Opus ファイルを用いて「ファイル入力（`transcribe_file`）」から再度文字起こしを再送することができます。

## 3. 再起動時のキュー永続化方針 (Queue Restart & Persistence Policy)

アプリケーションの予期せぬシャットダウン、PC 再起動、アプリ終了時におけるキューデータの保存・復元に関する意思決定です。

### 3.1. 決定内容（方針）

**「ジョブキューおよび未処理音声バッファの、再起動をまたぐディスク永続化（復元）は行わない」**

1. **完了済みジョブ（`done`）:** 
   - すでに文字起こしされたテキスト成果物は、ローカル保管庫（Vault）内に Markdown ファイル等（`.md` / `.txt`）として**ディスクへ非破壊保存が完了**しています。
   - 成果物自体が永続化されているため、キュー履歴をアプリ再起動後に復元する実質的な恩恵は薄く、ディスクへ不要なメタデータを書き留めることによるIO負荷を避けます。
2. **未処理ジョブ（`queued` / `running`）:**
   - 未処理ジョブの音声をディスクへ永続化（一時フォルダへ自動保存）することは、ユーザーが明示的に保存を選択していない音声データをディスクに勝手に残すことになり、**「ローカル完結・プライバシー重視」のデフォルトポリシーに反する**リスクを伴います。
   - また、アプリ再起動時に中途半端な音声ファイルを復元してバックグラウンドで文字起こしを勝手に再開することは、アプリ起動時の CPU スパイク（起動時間オーバーヘッド）を引き起こし、NFR（非機能要件）の起動パフォーマンス目標（≤ 1秒）を阻害します。

### 3.2. 技術的設計と動作
- アプリ起動時、Rust バックエンドの `JobState` および `JobQueue` はクリーンに初期化（空状態）され、フロントエンドの `jobs[]` 状態 runes もクリーンに開始されます。
- 常駐アプリとしてトレイ終了（Quit）時には、安全にすべての `queued` 音声バッファが解放されます。
